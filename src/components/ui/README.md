# 基础 UI 组件

这里是项目的基础 UI 层。新增页面或功能时，先从 `@/components/ui` 查找现有组件；页面只负责业务结构、布局和领域状态，不重复实现通用交互样式。

## 组件目录

| 组件 | 用途 | 常见入口 |
| --- | --- | --- |
| `Button` | 主要、次要、幽灵、危险和柔和操作 | 保存、取消、删除、展开操作 |
| `Card` | 统一容器、表面层级和悬浮反馈 | 模块、面板、信息块 |
| `Badge` | 状态、科目和轻量标签 | 状态、分类、风险提示 |
| `Checkbox` | 可访问的复选框 | 批量选择、完成状态 |
| `Switch` | 支持点击、键盘及拖动的开关；液态玻璃模式下交互时放大折射 | 设置项、专注选项 |
| `SegmentedControl` | 键盘可操作的分段选择，切换时玻璃指示条放大折射 | 计时模式、考纲方案 |
| `Slider` | 保留原生键盘和拖动操作的玻璃滑块 | 背景调节、学时占比 |
| `Select` | 统一下拉选择 | 筛选、配置、枚举选择 |
| `DatePicker` / `TimePicker` | 日期和时间选择 | 计划日期、时间段 |
| `Modal` | 对话框、确认和编辑流程 | 新建、编辑、确认 |
| `ProgressBar` | 进度展示 | 学科进度、任务进度 |
| `LoadingSpinner` | 加载中状态 | 异步加载、页面初始化 |
| `EmptyState` | 空数据和引导操作 | 无计划、无记录、无搜索结果 |

## 复用规则

1. 写模板前先搜索本目录；能用现有组件表达的场景，不要再写同类 `<button>`、表单控件或状态胶囊。
2. 页面样式只处理布局和业务语义。颜色、间距、圆角、阴影、字体和动效优先使用 `src/styles/variables.css` 的设计令牌。
3. 业务专属的尺寸、排列和状态可以放在页面的 scoped CSS 中；当同一组样式跨页面出现，立即提取为基础组件或明确的领域组件。
4. 只有在现有组件的语义、交互或可访问性确实不匹配时才新增基础组件。新增后必须：
   - 在本目录登记并从 `@/components/ui` 导出；
   - 提供清晰的 props / emits 和键盘、禁用、加载等必要状态；
   - 使用设计令牌，而不是复制一套颜色、间距和圆角；
   - 更新本目录说明，并让 `pnpm ui:check` 通过。
5. 不要为了“看起来差不多”复制已有组件的 CSS。若视觉确实需要例外，在 PR 描述中说明原因和适用范围。

## 引入示例

```vue
<script setup lang="ts">
import { Button, Card, EmptyState } from "@/components/ui";
</script>
```
