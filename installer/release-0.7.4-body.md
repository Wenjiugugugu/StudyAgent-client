## 概览

0.7.4 在 0.7.3 的进度联动基础上，继续补齐了计划、复盘、进度表和统计之间的数据闭环：历史任务完成状态会持久化，错过复盘窗口后系统能够依据最终状态生成可识别的默认复盘；进度表完成后自动进入强化阶段，目标截止日、日期与时区口径也统一处理。与此同时，本版完善了备份恢复与损坏配置保护，并为正式桌面发布补上完整质量门禁。

## 修复

### 进入强化阶段后仍被禁止安排复习任务

「总结与复习任务」开关（设置 → 学习偏好）本意是控制基础阶段的推进方式：开启后允许安排回顾、总结类任务，关闭则要求每天只推进新内容。但它此前是全局开关——当某科的知识点已经在进度表中全部达到「基础」，该科事实上已进入强化阶段（巩固类任务才应是主体），此时关闭开关会让系统在周计划里明确禁止出现任何「回顾/总结/复习/巩固」字样的任务，与强化阶段的学习方式直接冲突。

现在判定规则调整为按科目区分：启用进度表中的知识点全部达到「基础」及以上的科目视为已进入强化阶段，不再受该开关约束，周计划会明确要求为其安排巩固类任务（真题二刷、错题重做、限时模考、背诵复习等），并禁止为其虚构新的章节进度；其余仍处于基础阶段的科目继续遵循开关设置。该判定覆盖周计划生成、复盘后重排、排除日重排三条链路。

### 学完进度表后阶段状态没有同步

此前强化阶段只在生成计划时临时推断，State 中的科目阶段仍停留在 foundation，旧的当前重点也会继续影响后续提示。现在所有进度表保存入口统一检查当前启用表；当全部知识点达到「基础」及以上时，自动把该科从基础阶段提升为强化阶段，同时不会覆盖用户已设置的冲刺、模拟或完成阶段。

### 简报把未启用的考纲版本也计入剩余进度

此前每日简报汇总某科进度时遍历了该科所有进度表。例如实际启用数二时，数一和数三的待学节点也会被合并，导致 79 个数二知识点被显示成 343 个、基础阶段剩余时间被错误拉长。现在简报、确定性估时和计划生成统一按 active_id 选择当前启用表；active_id 失效时依次回退到 active_variant 和第一张表。

### 目标计划超期后直接失效

目标计划（设置截止日的规划区间）在到达截止日后的复盘中会被直接置为失效，只保留规划区间学时占比的回退。对于进度滞后的情况，实际上没有第二次机会——用户需要手动新建目标才能继续。

现在未达标的目标会自动顺延截止日（每次复盘顺延一天，直至达标），并保留一个「基准日 + 缓冲天数」的封顶上限：缓冲天数取设置中的每日学习时段跨度（夹在 7～180 天之间），配置为 0 表示不封顶。封顶日当天目标仍然生效，严格越过封顶日才真正失效。历史数据中已被置为失效的旧目标会在下次复盘时重新拉起。

### 日期、时区与截止日口径不一致

日期计算此前分散在多个模块，部分逻辑使用 UTC，部分逻辑使用本地时间，目标生命周期对「截止日当天是否生效」的判断也不一致。这会让中国标准时间凌晨 0 点到 8 点之间出现日期偏差，或者让目标在截止日当天复盘前就被判为过期。

现在日期运算统一使用中国标准时间，并共用同一套日期解析、周区间、天数差与截止日判断；截止日当天始终有效，下一天才进入顺延或过期判断。类似 2026-02-30 的格式正确但实际不存在的日期也会被拒绝。

### 错过复盘后历史记录永久缺失

过去如果用户没有在允许补录的时间内提交复盘，该日会一直显示为未复盘，任务最终完成状态也可能在跨日后随 current.state 被替换，历史计划无法准确还原。

现在每次读取今日计划、历史计划或周汇总时，系统会检查应补记的日期，并根据当日日计划中持久化的最终任务状态生成「系统默认复盘」。今日学习开始前仍可手动补昨天，超过窗口后才自动标记；历史页会明确区分系统默认复盘与用户主动复盘。任务勾选状态也会同步写回对应日计划，跨日后不会丢失。

### 默认复盘会虚增学习天数

如果把所有系统补记都视为学习日，即使当天没有完成任务、没有实际学习时长，也会增加累计学习天数和连续学习天数。现在用户主动提交的复盘仍代表一次实际学习；系统默认复盘只有在存在完成任务或实际时长时才计入统计。专注记录、计划记录和复盘记录之间的去重口径也保持一致。

### 专注计时与提醒状态不完整

专注模式此前没有完整保存运行阶段、暂停剩余时间、秒表起点、轮次和总时长，重启后可能无法恢复；休息阶段也没有完整进入历史统计。现在倒计时、正计时、暂停状态和番茄轮次统一持久化，短休息与长休息会写入专注记录；关闭自动休息时，学习倒计时结束后会继续正计时，直到用户主动开始休息。每日提醒统一按中国标准时间判断，并持久化当天已触发时刻，避免同一提醒重复弹出。

### 旧进度表知识点无法展开到原章节

部分旧进度表只有知识点的阶段名称，缺少章节 parent_id，或者章节 ID 修复后仍引用旧 ID，导致复盘和进度页无法把知识点正确放回章节。现在加载进度表时会按唯一章节标题安全补齐归属；遇到重复标题或无法唯一判断时保留原节点，不进行可能错误的强制挂靠。

### 桌面后端错误被示例数据掩盖

此前带回退的前端调用在 Tauri 桌面环境遇到后端错误时也会调用 Mock，磁盘写入失败、配置损坏等真实问题可能表现为操作成功或出现示例数据。现在 Mock 仅用于普通浏览器开发环境；桌面端会原样抛出后端错误，不再制造假成功。

### 损坏设置可能被默认值覆盖

设置文件无法解析时，前端曾继续填充默认配置，用户随后保存就可能覆盖损坏但仍可恢复的原文件。现在后端会先验证已有设置文件，读取失败时保留原文件；应用转到可重试的设置错误页，明确提示检查目录权限或从备份恢复。

### 备份遗漏新增数据域且无法发现篡改

旧备份只包含早期数据目录，遗漏进度表、自适应规划和分析数据，导入时也无法判断压缩包是否缺文件或被修改。现在持久化目录使用统一清单，完整覆盖状态、计划、复盘、设置、教材、专注、进度表、自适应规划与分析数据；新备份附带格式版本、应用版本、文件大小和 SHA-256 清单，导入会在替换当前数据前完成逐文件校验。旧格式备份仍可继续导入。

## 优化

### 复盘与计划外学习

复盘历史现在会显示计划任务的最终状态、预估与实际时长、阻碍因素等信息，并明确标识系统默认复盘。计划外学习继续支持章节级快捷推进，同时可以展开章节逐条选择知识点；当系统记录快于实际进度时，也可以在确认后回退纠偏。

### 进度表管理体验

进度表页面重新整理了表切换、章节折叠、完成统计、节点状态、拖拽排序、重命名与节点编辑交互；新增知识点时会写入明确章节归属。AI 生成进度表在调用前增加风险说明，生成结果必须预览确认后才会保存，提醒用户按教材、课程与考试范围自行核验。

### 首次引导与界面一致性

首次引导整合考试年份与科目版本、每日学习时长、学科占比、任务粒度、复习与计时偏好、内置进度表、滴答清单、开机启动和 AI Provider 配置，并提供快速配置与完整配置路径。页面视觉、基础 UI 组件、明暗主题、侧边栏交互和键盘可访问性同步统一。

### Markdown、公式与输入组件

Markdown 渲染补齐有序/无序列表切换、标题层级、代码占位和安全外链属性，LaTeX 清理规则扩展到 KaTeX 生成的 MathML 元素与必要属性。Select 为每个实例生成唯一的 ARIA 关联 ID，并完善键盘高亮；日期和时间选择器的相邻月份日期、禁用状态和选中项滚动也更稳定。

## 安全与发布

- 正式构建默认不注册调试路由，也不在侧边栏暴露诊断入口；支持包可通过显式构建变量开启。
- Windows 发布脚本不再依赖开发者机器的硬编码路径，支持独立 Cargo 编译缓存并在打包后输出安装包大小与 SHA-256。
- CI 增加格式、类型、ESLint、前端测试、版本一致性、UI 组件登记、Rust fmt、Clippy、Rust 测试和真实桌面 EXE 构建门禁。
- 新增隐私政策、安全说明、贡献指南、Issue/PR 模板和 UI 组件使用文档，明确本地数据、AI 网络请求、日志、备份和漏洞报告边界。
- 新增 Mock 隔离、设置错误、备份覆盖与篡改检测等回归测试，并统一代码格式与 lint 规则。
